Five ways to draw Nova in a terminal

Every option below is built from characters on a grid, the same way the TUI will print it. What you see here is what a terminal shows, drawn cell by cell at one size, so none of it is smoothed or scaled down from a picture.

Motion
Terminal

Why the current splash turns to mush

From reading tui/splash/splash.go, my read is this:

  • The mark is a 97 by 49 cell picture. The full size needs a terminal about 99 columns wide and 29 rows tall, so most windows fall to the Half or Quarter level.
  • Those levels average 2 by 2 or 4 by 4 source cells into one half-block. The mark has hundreds of cells at 5 to 30 percent opacity (the filaments and outer shells), and they blend into the background as muddy in-between colours.
  • A picture shrunk to a character grid loses its shape first. A shape designed for the grid, like the options below, keeps it.
A

Block wordmark

The name as chunky letters with a light sweeping across. Plain, loud, readable at a glance. The sweep runs from blue through white, and warm cream is the brightest point.

54 × 6 cells27 × 3 compactglyphs: █ ▀ ▄Truecolor for the sweep
For
  • Instantly legible, which fixes the main complaint
  • Compact 3-row version for headers
  • The same bitmap can generate the README SVG
Against
  • Says "nova", says nothing about stars
  • Close to every other block-letter banner
B

Slash fill

The Crush approach: the letters are filled with diagonal strokes and sit on an offset shadow. The shadow is the warm companion colour, so the brand idea survives.

56 × 7 cellsglyphs: ╱Truecolor, shadow needs a second hue
For
  • Most character, and it looks hand-made
  • The texture hides the blocky edges of the bitmap
Against
  • Closest to Crush, so it can read as a copy
  • Needs 57 columns and loses the shadow with no colour
C

Outburst

A splash that plays the event itself on a 9 second loop. A dim star ignites, the diffraction spikes flare, a clumpy shell of gas expands and cools from blue to orange, then the name appears. The small orbiting dot is the surviving companion.

64 × 19 cellsglyphs: ─ │ ◆ ✦ ● · : + *Truecolor, animated
For
  • The only option that actually shows a nova
  • Procedural, so there is no embedded cell data to maintain
Against
  • Needs animation ticks on the splash screen
  • Frozen, it is a dim star with dust, so a static screenshot undersells it
D

The O is the nova

Thin lowercase letters where the o is a ring of ejected gas around a bright core. A warm companion circles the ring and leaves a cool trail. It is a wordmark first and an astronomy joke second, and it shrinks to n◉va in one line.

46 × 5 cellsglyphs: █ ◉No-colour version keeps the ring and core
For
  • Smallest footprint of the big options
  • Carries the name and the idea in one shape
  • Reduces cleanly to a one-line header
Against
  • Subtle: the ring reads as an ordinary "o" until you look
  • Thin strokes are less bold on a busy screen
E

Quiet star

The calmest option. A single bright star with long diffraction spikes sits in a sparse, twinkling field, with the name set small underneath and a warm companion off to one side. It is a poster more than a logo.

64 × 17 cellsglyphs: ─ │ ◆ · + .Works in two colours
For
  • Most atmosphere for the least ink
  • Easy to scale: spikes just get shorter on narrow terminals
Against
  • The name is small, so it is a mood and not a brand mark
  • Needs a separate wordmark for the README

My recommendation

Use D as the logo and E as the splash backdrop. D gives you a wordmark that works in the README, the header and the splash, and it keeps the warm companion from the current brand. E gives the splash screen its atmosphere without the clutter. Keep A as the bold fallback if D looks too delicate on your terminal. C is the one to pick if you want the splash to be an event, but it costs an animation loop.

That is a taste call, so treat it as a starting point. I also have not tested any of this in your real terminal font, which is the main thing that can change how the glyphs look.

What I need from you

  1. Which direction, or which two to mix? Any combination works, for example D for the logo and C for the splash.
  2. Should the README banner change too? The same bitmap can generate an SVG, so the GitHub image and the TUI would match. That would replace the current 135 KB cell mark.
  3. Keep the palette? Everything here uses the existing four colours (blue, white, cream, orange). A single-accent version is easy if you want it calmer.
